## Protobuf in `record` (2026-11-14)

Hand-written decoder (`src/otlp-protobuf.ts`), no dependency; Alper chose this over a protobuf library. Built from real exports, not from the .proto files alone: one JS tracer with two span processors sent the same spans through `exporter-trace-otlp-http` and `exporter-trace-otlp-proto` 0.223.2; decoding the 4 protobuf bodies gives exactly the 4 JSON bodies' spans, apart from defaults protobuf omits (fixture `otel-js-exports.ndjson`). Python (`opentelemetry-exporter-otlp-proto-http` 1.45.2, protobuf 7.36.2, Python 3.14.2) has no JSON exporter, so its 4 protobuf bodies were checked against the SDK's in-memory spans written out by the script: equal for all 8 spans, including ints 2^62+1, -2^63, 2^63-1 and all five span kinds; only span flags (256) differ, which the SDK's view doesn't carry (fixture `otel-python-exports.ndjson`). Recorded from protobuf, the JS trace audits exactly as recorded from JSON; the Python trace audits to a total computed from the script's usage numbers. End to end: `burnlint record` received a gzipped protobuf export from a Python SDK configured only by `OTEL_EXPORTER_OTLP_ENDPOINT`. Hand-built messages cover what neither API can send (kvlist and bytes values, NaN, uint64 times at the max, unknown fields of every wire type) and malformed input (truncated, lengths past the end, wrong wire type, group wire type, varints over 10 bytes, field 0, nesting over 64 levels): refused with 400 and a google.rpc.Status, nothing written. Not done: gRPC.

## Real captures (roadmap step 2)

Real captures from agent frameworks builders use (OpenAI Agents SDK, LangGraph, Vercel AI SDK `ai.*`, OpenInference), through `record`. Needed before `diff`: it must be designed against real before/after traces, and they show whether the waste rules find money outside Claude Code. In progress (2026-11-13): Vercel AI SDK first, on Claude Sonnet 5.5; agent in `bench/ai-sdk/`, Alper runs it on his key. First capture (`captures/ai-sdk.jsonl`, 12 runs, ~$1.5): semconv cost matched an independent recomputation on all 9 runs. It showed cache-thrash overstating savable and firing on a big tool result on a cold cache (both fixed), and failed runs counted as $0 runs (fixed). Second capture (`captures/ai-sdk-2.clean.jsonl`; the raw file also holds 2 mock traces, dropped in the clean copy): 34 semconv + 9 legacy runs, ~$7.4, two phases per run (answer, then check), variants normal/prefix/nocache/reread x 3. Cost and cache-thrash savable matched independent checks on all 34; burnlint's prefix savable roughly equals the measured prefix-minus-normal cost difference (review $0.40 vs +$0.42, explain $0.037 vs +$0.043, principle $0.101 vs +$0.098). Harness bug: in AI SDK 7 `result.response.messages` is only the last step (all steps: `result.responseMessages`), so every check phase lost its tool results; fixed in agent.mjs after the run, so the reread variant was not a valid test (also: rereads came with different, overlapping ranges, which `reread-unchanged` doesn't match). That bug showed a burnlint gap, now fixed: a trace can hold several conversations, so the OTLP reader marks a call whose prompt shrank (under 80% and 1,024+ tokens below the previous) as a context reset. Noise is large (principle nocache $0.11-0.24 over 3 runs). Done since: the `ai.*` (LegacyOpenTelemetry) mapper and fixtures for both formats; all 43 runs match independent cost and savable checks. Third capture (`captures/ai-sdk-3.jsonl`, 2026-11-13, normal,reread x 3 tasks x 3, $1.73, 18/18 pass): cost matched an independent recomputation from the SDK's usage on all 18 (official Sonnet 5.5 cache read is $0.10/MTok, 0.05x; the bench's `PRICE` equals LiteLLM's, so it isn't an independent check). reread costs +36-42% over normal, but the model rereads with new ranges, rarely the same one: exact-match reread-unchanged fired in 2/9. Now matches overlapping ranges by per-line hashes; on this capture it fires on 9/9 reread and 0/9 normal, and its repeated lines match an interval calculation from the requested ranges (fixture `ai-sdk-v7-reread.jsonl`). Its savable (repeated tokens carried) is a small part of the reread cost difference: most of that is the extra calls that reread, which aren't counted as avoidable (a reread moves content to the end of context and may help; a trade-off until outcomes show otherwise). `no-prompt-cache`: on all 18 ai-sdk-3 runs with their caching stripped, its savable matched what caching really saved within 0.1%; on a real nocache run (`captures/ai-sdk-4.jsonl`, principle, $0.119; fixture `ai-sdk-v7-nocache.jsonl`) it fires with $0.057 savable (measured nocache minus normal mean: $0.052), and the AI SDK reports zero cache fields as 0, not absent. It errs high when the prefix changes every call while the prompt grows (a timestamp in the system prompt). A reread-only call's cost is shown in `reread-unchanged` details, never counted (independent review, 2026-11-13). Prefix check: where the trace records the prompt, `promptKeys` (hashes of tools, system, each message, blocks per message) let `no-prompt-cache` count a hit only on an unchanged prefix (else "up to", an upper bound) and let `cache-thrash` name what changed. Checked on a real `prefix` run (`captures/ai-sdk-5.jsonl`, fixture `ai-sdk-v7-prefix.jsonl`): system prompt changed on 5 of 6 calls; all 107 steps of ai-sdk-3 and the nocache run unchanged; the prefix run with caching stripped gets no no-prompt-cache finding. Gap: caching off on a volatile prefix reports nothing (caching as it stands would save nothing; the stable-prefix saving isn't claimed). Follow-up, needs one real capture each: a lost automatic cache on OpenAI/Gemini (prefix-matched too; they report cache reads but no writes, so `cache-thrash`, which needs a rewrite, never fires there). `carriedCost` stops at a context reset; `reread-unchanged` exact matches need both results known. The 3 failed legacy runs vanish: legacy spans aren't recognized as model calls yet. An earlier attempt hidden by an SDK retry is invisible in the trace (review-normal step 2: 66s, reads a cache no earlier call wrote); don't flag warm starts as retries. ## diff (roadmap step 3)

`burnlint diff <base> <head>`: same tasks before and after a change. v1 done (2026-11-13, design reviewed independently): runs compared within groups (`Run.labels`: OTLP root-span scalar attributes, never content keys, plus `gen_ai.agent.name`, filled from `ai.telemetry.functionId` for `ai.*` spans; Claude Code `project`); default group `gen_ai.agent.name`, then `project`, else one group; an unknown `--group-by` key is refused. Headline is group means weighted by base's mix (pooled means shown when the mix differs); per group mean/median/min/max, calls, prompt and output tokens, cache share. Stratified permutation test (exact up to 200k relabelings, else 20k sampled with a fixed seed); verdict two-sided, `--fail-above` one-sided and only on a clear rise (an unclear rise passes with a warning); unpriced calls on either side make it `can't tell` (gate exits 2); failed runs and model changes noted. Checked on ai-sdk-3 normal vs reread: group means and +38.1% match an independent recomputation from the SDK's usage, p = 1/8000 one-sided as computed independently. Power at bench noise (simulated): 3 runs per task see +10% 56%, +15% 86%, +20% 98%. The content filter on label keys also drops harmless keys (`bench.input_id`); later, let the user allow keys explicitly (Alper, 2026-11-14). A/A (2026-11-14): the bench's tools read the live repo, so a rerun a day later (`captures/ai-sdk-6.jsonl`) cost +11% and the gate fired correctly: `src/` had grown 1,128 lines (prompt tokens explain +79%, principle +39%).
